# 管理端学习资料：筛选、上传侧栏与 CEO 批量删除对接

日期：2026-10-18

范围：Quanta 官网管理端 Web / 移动端。与 OAuth 对接文档完全独立；不涉及 Challenge、登录授权、成员资料维护或塔员端重设计。

## 1. 本次交付和上线前提

前端按确认设计提供：

1. “全部资料”放在左侧，与培训资料、技术分享、项目实践并列。再次点击当前类型，回到当前部门全部资料。
2. 右侧上传抽屉（Web 440px，窄屏 ≤700px 全宽），沿用当前部门及类型、多文件队列、上传进度、失败重试。
3. CEO 当前页勾选、全选、取消选择、确认后批量删除。

**本次不实现或部署真实后端新接口、不执行数据库迁移，不执行真实资料删除。** 浏览器验证使用明确的受控测试响应，不能作为生产接口已可用的依据。

提交前已核对并同步官网主分支 `7ffe84e`：Java 已提供资料目录及 `folderId` 能力，`QtMaterialController` 仍只提供单条删除，尚无本次批删接口。请后端核对实际部署版本与目录迁移是否就绪。下文区分“继续复用的既有约定”和“本次新增接口”。真实环境 `VITE_USE_MOCK=false` 时，前端不会用 Mock 补齐批删，也不会在批删失败后循环调用单删。

## 2. 权限边界

| 操作 | 权限要求 |
| --- | --- |
| 列表、分类读取和下载 | 沿用现有已登录塔员及资料访问范围规则 |
| 上传、分类初始化 | 沿用现有上传业务身份和部门范围；CEO/现有超管可选部门，其他可上传的管理身份限本部门 |
| 单条删除 | 保持现有接口和鉴权，不在本次扩大或收紧 |
| **批量删除** | **显式角色 `ceo` 且具备 `qt:material:remove`（全权限 `*:*:*` 也满足权限项，但不能替代 `ceo` 角色）** |

前端来自 `/getInfo` 的 roles/permissions 控制入口，但**后端必须从当前已认证用户重新判断**，不得相信请求体提供的角色、用户ID或前端按钮状态。登录标识、JWT和跨域凭证处理继续沿用官网已有策略，不新增身份透传参数。

特别注意：现有前端 `hasRole('ceo')` 会兼容 `admin`，现有后端 `QtAuthUtils.isCeo()` 也会兼容超级管理员。这两个通用方法不能直接用作本次“仅 CEO”的完整判定。后端应读取可信角色键集合，精确匹配 `ceo`，再检查删除权限；不能只凭 `@ss.hasRole('ceo')`（若其内部具有超管放行逻辑）或 `requireCeo()` 就通过。`admin`、`qt_mgmt`、`qt_manager` 若无显式 ceo 角色，批删必须拒绝。

## 3. 筛选与分类：复用既有约定

### 部门与固定类型

部门码：`FRONTEND` / `BACKEND` / `PRODUCT` / `DESIGN`。

| UI 类型 | 前端状态码 | 一级目录精确名称 |
| --- | --- | --- |
| 培训资料 | TRAINING | 培训资料 |
| 技术分享 | TECH | 技术分享 |
| 项目实践 | PROJECT | 项目实践 |

类型码是前端状态，不直接作为新增后端字段；前端按部门、`parentId=0`、精确目录名查真实 `folderId`，不写死ID。界面不展示目录树或新建目录。

读取目录：`GET /qt/materials/folders?category=FRONTEND&parentId=0`

```json
{
  "code": 200,
  "data": [
    { "folderId": 31, "category": "FRONTEND", "parentId": 0, "folderName": "培训资料" },
    { "folderId": 32, "category": "FRONTEND", "parentId": 0, "folderName": "技术分享" },
    { "folderId": 33, "category": "FRONTEND", "parentId": 0, "folderName": "项目实践" }
  ]
}
```

类型列表：`GET /qt/materials?category=FRONTEND&folderId=31&pageNum=1&pageSize=20&categoryScope=STANDARD`。

全部资料：同一部门请求移除 `folderId`，**必须包含未分类历史资料**（folderId=null/0）；不表示跨部门读取。

搜索：沿用既有后端 `fileName` 搜索忽略 `folderId` 的约定；前端请求 `category` + `fileName` 并明确提示“当前部门全部类型”。清空搜索恢复搜索前类型；不在客户端过滤单页数据伪造分页结果。

列表响应沿用 `code / rows / total`：每项至少有 `materialId,category,fileName,fileSize,uploaderName,uploadTime,downloadUrl`；建议携带 `folderId,folderName`，便于全部资料态显示正确类型。

## 4. 上传侧栏：复用现有 POST，不新增批量上传接口

列表的类型可以切回全部；**上传的类型必须三选一**，不存在“上传到全部资料”。列表有选定类型则带入；列表为全部时默认培训资料，并显示请确认类型。上传部门由已有身份策略决定，后端必须复核。

`POST /qt/materials`，`multipart/form-data`，每个文件单独请求：

| 字段 | 说明 |
| --- | --- |
| file | 单个文件，前端不手动设置 multipart boundary |
| category | 四个标准部门码之一；部门受限账号只能本部门 |
| visibility | 固定 `MEMBER`，对全部塔员可见 |
| folderId | 所选部门下三固定类型之一的真实一级目录ID |

最多选择20个文件，单文件最大20MiB（20×1024×1024字节）；扩展名 pdf/doc/docx/ppt/pptx/xls/xlsx/txt/md/jpg/jpeg/png/webp。后端同时验证真实大小、文件类型、安全文件名及存储位置，不只相信扩展名。每文件前端超时120秒，队列串行上传；成功项不重复上传，失败项可重试。

尚无目标目录时，仅在用户点击确认上传后复用：

```http
POST /qt/materials/folders
Content-Type: application/json
```

```json
{ "category": "FRONTEND", "parentId": 0, "folderName": "培训资料" }
```

创建成功可仅返回 `{ "code":200 }`，前端会重新读取目录获取ID；同级并发重名按409处理，再读取已有同名目录。不在浏览、筛选、打开侧栏时隐式建目录。后端校验 folderId 所属部门、目录可用状态，不能把文件归入其他部门目录。

当前本地 Java 上传检查 `qt:material:add`，而前端既有上传策略允许部门经理等管理身份上传，即使其 roles/permissions 未单独带此权限。此处是既有前后端策略差异，**不是本次要求放开权限**；后端请按原有业务决定为可上传身份分配权限，或使接口鉴权与既定策略一致。未对齐时应明确403，不假成功。上传已有成功文件后刷新列表；若仍按其他关键词筛选，该文件不一定立刻出现在当前结果中。

## 5. 新增 CEO 批量删除接口

### 请求

```http
POST /qt/materials/batch-delete
Authorization: Bearer <当前官网 Access Token>
Content-Type: application/json
```

```json
{ "materialIds": [101, 102] }
```

规则：1–20个唯一正整数ID，当前前端使用 JavaScript 安全整数（≤9007199254740991）；不接受字符串、0、负数、小数、重复ID、空数组及超限数组。后端不可接受任意where条件、部门或“删除全部搜索结果”等扩展参数。当前UI仅勾选当前页，但后端仍须对每个ID独立检查真实资料范围；不能只信任客户端当前部门。

### 成功响应：必须完整确认全部目标

```json
{
  "code": 200,
  "msg": "批量删除完成",
  "data": {
    "deletedIds": [101],
    "alreadyDeletedIds": [102]
  }
}
```

- `deletedIds`：本请求确实删除的ID。
- `alreadyDeletedIds`：已不存在、已被删除的请求ID，作为幂等成功处理（仅在通过CEO鉴权之后判定）。
- 两个数组都必须存在，互不重复；并集与请求ID集合完全一致，不得多报、漏报，顺序不限。没有已删除目标时返回空数组，不可省略字段。
- **不使用部分成功协议**。存在无权删除/被保护/存在业务引用不可删除等目标，整个批次拒绝，其他目标也不能先删。已经不存在的目标例外，归入 alreadyDeletedIds。
- 前端不会把仅有 `{code:200}` 或 `deletedCount` 认作完整成功，会提示结果未确认并重新读取列表核对。
- 重复同一请求应安全返回 alreadyDeletedIds，不产生重复文件清理或错误地删除其他记录。不提供自动循环重试或单删降级。

### 后端执行顺序与一致性

1. 鉴权：已登录、显式 ceo 角色、删除权限；无权时在读取文件详情或执行任何删除前拒绝。
2. 校验请求，限制20项，参数化查询，加载并锁定/使用条件更新全部目标，完整检查可删条件及并发状态。
3. 在事务中统一删除/逻辑删除资料记录，更新关联计数和引用，保证失败整体回滚；不要直接复用绕过身份检查的批量Mapper。
4. 文件物理删除不具备数据库事务回滚能力。建议记录待清理任务/outbox，与资料删除同事务提交后清理文件，失败可重试。清理路径必须来自可信存储记录，校验位于配置的资料存储根内，不接受客户端文件路径；不要在校验完所有目标之前删除文件。
5. 审计记录操作人、时间、请求ID、目标ID、实际删除/此前已删/失败原因；失败也记录，不记录Token或文件正文。对并发请求保持事务隔离/锁定，避免审计结果与实际删除不一致。

“无法恢复”指当前产品没有用户恢复入口；备份/保留策略由后端运维决定，UI不承诺物理文件即时永久擦除。

### 错误约定

沿用官网 `code/msg`，HTTP状态码也应尽量一致。

| code / HTTP | 含义与前端行为 |
| --- | --- |
| 400 | 参数不合法；不删除，保留勾选并提示 |
| 401 | 未登录/过期；沿用现有双Token刷新与重新登录逻辑，刷新失败不提交删除 |
| 403 | 非ceo或缺权限；不删除，提示，后续按新权限隐藏入口 |
| 409 | 业务引用/保护记录/并发冲突；全批未执行，提示重新核对 |
| 404/405/501 | **整个批删端点不可用**，不是单条资料已不存在；提示后端未接通，不降级为单删 |
| 500/503或网络超时/断连 | 前端无法确定事务是否已提交，提示“删除结果未确认”，清空选择并重新拉取列表；刷新仍失败显示重试，不谎报成功/未删除 |

错误示例：`{ "code":403, "msg":"仅 CEO 可执行批量删除" }`。

## 6. 前端交互约束

- 全选只选当前页，Web与移动端共用同一份勾选状态；选择0项时批删按钮禁用。
- 更换部门、类型、搜索条件、页码、列表刷新或批删权限变化时清空勾选。输入搜索词但尚未提交不改变列表范围。
- 删除确认列出数量和文件名（文本渲染，不能执行文件名中的HTML），提示不可恢复。取消/关闭不请求。
- 确认中及提交中锁住筛选、选择、上传入口、分页和其他删除入口，避免重复提交；确认通过后再次检查前端角色，但真正安全边界仍在后端。
- 成功重新拉取服务器分页；删空末页时回到有效页，不只在前端删DOM。删除已成功但列表刷新失败时分别报告，不把删除说成失败。
- 保留原单条删除；保留塔员端现有页面样式和使用方式。

## 7. 后端联调验收清单

- [ ] ceo + remove权限或*:*:*：可批删；ceo但无删除权限：403。
- [ ] admin/qt_mgmt/qt_manager/普通塔员，含仅有*:*:*但无ceo角色的账号：批删403；不改变其原单删权限。
- [ ] 空/重复/非法/21个ID：400，资料和文件均未变化。
- [ ] 两份有效资料：完整 deletedIds；混合此前已删目标：对应 alreadyDeletedIds，安全重复请求。
- [ ] 一份不可删或越权：409/403，其他有效资料也不删除。
- [ ] 并发删除、请求已提交但响应断开、文件清理失败：记录、计数、审计、重试均一致。
- [ ] 目录实际接口可读，folderId与部门绑定；旧资料仍能在全部资料中读取；关键词搜索行为与约定一致。
